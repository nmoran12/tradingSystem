# Replay Visualiser UI (spike)

This document describes the prototype replay visualiser for `cpp-low-latency-orderbook`. It is intended for debugging, learning, and portfolio demonstration, not for production trading.

## Architecture

```text
Binary/CSV input → C++ replay CLI (headless)
                 → optional NDJSON file export (7A)
                 → optional localhost SSE stream (7B, backend)
                 → React + Vite replay UI (file, scenarios, or live SSE follow)
```

Roadmap: [REPLAY_VISUALISER_ROADMAP.md](REPLAY_VISUALISER_ROADMAP.md).

- The **C++ engine remains headless and performance-focused**.
- Visualisation output is **optional** and only generated when explicitly requested.
- Benchmarks and Release workflows remain unchanged unless you pass visualisation flags.

## Generating visualisation output

Replay visualisation uses the same **`schemaVersion: 1`** JSON record for both file export and live stream. Choose one mode per run:

| Mode | CLI | Output |
|------|-----|--------|
| **File export (7A)** | `--export-visualisation <path.ndjson>` | NDJSON file (one object + newline per command step) |
| **Live stream (7B)** | `--stream-visualisation <host:port>` | HTTP Server-Sent Events on loopback while replay runs |

Both are **opt-in** and only available on the **`--binary-engine`** path (not `--engine` CSV or `--replay` market events).

### File export

The flag name is exactly `--export-visualisation` (there is no `--export-viz` alias).

```bash
./build/cpp-low-latency-orderbook \
  --binary-engine /path/to/order_commands.obk \
  --export-visualisation replay.ndjson
```

The repository ships `data/sample_commands.csv` but not a committed `.obk` file (`*.obk` is gitignored). Generate a binary command file with the binary writer/tests/workload tooling, then pass it to the CLI above.

Each line contains:

- `schemaVersion` — integer schema version (currently `1`)
- `index` — zero-based step index
- `commandType` — `new`, `cancel`, or `modify`
- `side` — `buy`, `sell`, or `unknown`
- `orderType` — `limit` or `market`
- `orderId`, `price`, `quantity`
- `symbol` — command symbol string (e.g. `DEFAULT`)
- `bestBid`, `bestAsk`, `spread` — top-of-book summary after the command
- `restingBidLevels`, `restingAskLevels` — **shallow export:** at most one aggregated level per side (best bid / best ask price only). Not full book depth.
- `trades` — executed trades for this command (price, quantity, and order IDs)
- `totalRestingOrders`, `totalRestingQuantity` — summary book stats

Example (one line):

```json
{
  "index": 12,
  "commandType": "new",
  "side": "buy",
  "price": 10100,
  "quantity": 50,
  "bestBid": 10100,
  "bestAsk": 10200,
  "spread": 100,
  "restingBidLevels": [
    { "price": 10100, "quantity": 120 }
  ],
  "restingAskLevels": [
    { "price": 10200, "quantity": 80 }
  ],
  "trades": [
    { "price": 10150, "quantity": 20 }
  ],
  "totalRestingOrders": 8,
  "totalRestingQuantity": 500
}
```

## Running the UI

The UI lives under `ui/replay-visualiser/` and is built with React + Vite.

From the project root:

```bash
cd ui/replay-visualiser
npm install
npm run dev      # for local development
npm run build    # for a production bundle
```

Then open the dev server URL (or `dist/index.html` after a build) and either:

- **Load a bundled scenario** from `public/` (see below),
- Use the file picker to load NDJSON generated by the C++ CLI (`--export-visualisation`), or
- **Connect to a live stream** (see [Live follow](#live-follow-7b-ui) below).

### Live follow (7B UI)

Proof-of-concept **live mode** uses the browser `EventSource` API to append `schemaVersion: 1` steps as the C++ backend streams them.

**1. Start the backend** (blocks until a client connects):

```bash
./build/cpp-low-latency-orderbook \
  --binary-engine /path/to/order_commands.obk \
  --stream-visualisation 127.0.0.1:9000
```

**2. Start the UI** (separate terminal):

```bash
cd ui/replay-visualiser
npm run dev
```

**3. In the UI** — use the **Live stream** section:

- Stream URL (default): `http://127.0.0.1:9000/stream`
- Click **Connect** (while the backend is waiting for a client)
- Steps append as they arrive; the view **follows the newest step** by default
- Use **Step back** / **Follow live** to inspect earlier steps without losing the stream
- **Disconnect** when finished

**Order matters:** start the C++ process first, then connect from the UI (or `curl -N http://127.0.0.1:9000/stream`).

Live mode limitations:

- **Localhost only** — same as the backend stream endpoint
- **No reconnect/backpressure** — disconnect on error; connect again manually
- **No process launcher** — you start the C++ CLI yourself
- File upload and bundled scenarios remain available; loading a file disconnects the live stream

### Bundled UI samples (demo fixtures)

Files under `ui/replay-visualiser/public/` (`sample-replay.ndjson`, `sample-deep-book.ndjson`, `sample-crossing-trades.ndjson`, `sample-spread-movement.ndjson`) are **demo fixtures** for the UI. Some scenarios show **multiple price levels** per side to exercise the ladder layout. The current C++ exporter emits **only the best level per side**, so those richer scenarios are not necessarily reproducible from `--export-visualisation` until depth export is extended. Prefer CLI-generated NDJSON when validating export behaviour.

## What the UI shows

Current prototype features:

- **Replay controls**
  - Load sample replay
  - Play / pause
  - Step forward / back
  - Reset
  - Current step index and total steps

- **Order book ladder**
  - Bids and asks in separate tables
  - Price and quantity per level
  - Highlighted best bid / best ask

- **Trade tape**
  - Recent trades (price and quantity)
  - Grows as you advance through the replay

- **Market summary** (current step)
  - Best bid / best ask
  - Spread
  - Total resting orders
  - Total resting quantity
  - Total trades so far

- **Run summary** (7C — whole replay)
  - Informational metrics derived **client-side** from all loaded `schemaVersion: 1` steps
  - Includes totals (steps, trades, traded quantity), final book snapshot, and min/max spread and resting stats where available
  - Updates when you load a file or scenario, and **grows during live stream** as new steps arrive
  - **Not** Release benchmark throughput or latency — see [BENCHMARKING.md](BENCHMARKING.md) for the real benchmark workflow

### Run summary panel (7C)

The **Run summary** section aggregates metrics from every replay step currently in memory:

| Metric | Meaning |
|--------|---------|
| Total steps | Number of visualisation records loaded |
| Total trades | Sum of trade objects across all steps |
| Total traded quantity | Sum of trade quantities |
| Steps with trades | Commands that produced at least one trade |
| Final resting orders / quantity | Values from the **last** step (by `index`) |
| Final best bid / ask / spread | Top of book after the last step |
| Min / max spread seen | Range over steps with a non-null `spread` |
| Max resting quantity / active orders seen | Peak values across steps |

**Sources:** bundled scenarios, uploaded NDJSON (`--export-visualisation`), or live SSE (`--stream-visualisation`) — same step shape for all modes.

**Scope:** educational and debugging only. No C++ schema changes; no benchmark binary ingestion. For Release measurements use `matching_engine_benchmark`, `binary_protocol_benchmark`, and [BENCHMARKING.md](BENCHMARKING.md).

## Live streaming (7B — backend)

7B adds an **opt-in** localhost HTTP/SSE stream using the **same** `schemaVersion: 1` JSON record as file export. See [Live follow](#live-follow-7b-ui) for UI usage.

```bash
./build/cpp-low-latency-orderbook \
  --binary-engine /path/to/order_commands.obk \
  --stream-visualisation 127.0.0.1:9000
```

Debug without the UI:

```bash
curl -N http://127.0.0.1:9000/stream
```

Each replay step is one SSE frame:

```text
data: {"schemaVersion":1,"index":0,...}

```

### Stream limitations (proof-of-concept)

- **Localhost-only** — endpoint host must be `127.0.0.1` or `localhost`; bind is always loopback.
- **Single client** — blocks in `wait_for_client()` until one connection is accepted.
- **Non-production** — no TLS, auth, backpressure, or multi-client fan-out.
- **No matching-core changes** — `MatchingEngine` / `OrderBook` logic unchanged; benchmark binaries unchanged unless you pass stream flags.
- Normal `--binary-engine` (no extra flags) and `--export-visualisation` behaviour are unchanged.

## Out of scope (for this spike)

- Production-grade reconnect, auth, or multi-client streaming
- WebSockets or production HTTP gateways
- React routing, authentication, or multi-page app
- C++ GUI frameworks (Qt, Dear ImGui, etc.)
- Production trading UI or real exchange connectivity
- Changes to matching semantics, binary protocol layout, or replay results

## Limitations and follow-ups

- C++ export depth is **shallow (BBO only)** — one aggregated level per side at the best price. Full book depth would require additional introspection APIs and exporter changes.
- Bundled multi-level NDJSON in `public/` is for UI demonstration; align or regenerate from CLI export when closing 7A.
- NDJSON schema may evolve as the visualiser grows (keep `schemaVersion` stable and bump it when fields change).
- A small chart (e.g. best bid/ask over time) can be added in a later iteration once the basic replay flow is stable.
